# 蒸馏处理协议

## 目标与边界

目标是让值得保留的信息都有可解释的去向，同时避免把 Agent 建议、工程状态或未经授权的信息写成人的记忆。质量包含召回、归属准确、去重正确、受众安全和保存真实，不能只看新增数量。

采用现有 Skill + scripts + 目标接入：规则处理语义，脚本核对结构，目标完成持久化。只追加文字规则无法检查漏处理和统计矛盾；新增后台服务、数据库或全量日志监听则超出当前需求。审计只使用本轮范围和按候选检索的现有记录。

## 六个阶段

| 阶段 | 输入与动作 | 完成证据 |
| --- | --- | --- |
| 1. 输入覆盖 | 划定本轮消息、指定材料、已指出漏项；还原指代和纠正 | 输入清单具有来源定位；截断摘录已补足任务范围 |
| 2. 候选提取 | 先列用户表达，再独立评估资料、概念、待办、片段 | 每个输入关联候选或具体排除理由；一句可拆多个候选，多句可合成一个 |
| 3. 分类与证据 | 区分主体、对象、立场、发生时间、原话、归纳和未知 | 五类逐项判断；个人判断须有本人陈述，想法无需先实施 |
| 4. 目标授权和去重 | 按材料内容及受众选目标，读取同对象相关条目 | 候选逐目标确定新增、补全、变化、重复或不能保存的原因 |
| 5. 保存验收 | 重读、最小写入、目标校验、回读核对字段与身份 | 新增/更新有目标稳定身份及校验和回读证据；失败单独保留 |
| 6. 结果核对 | 审计输入、候选与目标结果；生成分目标统计 | 审计通过；最终回复与实际结果一致，Git 与部署另列 |

输入清单以具有独立含义的消息或材料段落为单位；先根据原始范围建立，再提取候选，不从候选反推输入清单。任务完成、提交请求通常可排除；“不要加服务，沿用现有脚本”同时包含技术选择，不能因为句式是命令而整句排除。用户质疑漏记时核对被指出原话，不把修复指令本身凑成新的个人经历。

候选粒度按事件与独立用途确定，不按消息条数或措辞层次拆分。同一讨论先表达通用判断、再补充其在当前项目的落点，且立场与依据没有变化时，合为一个候选，正文同时保留观点和项目语境，引用两处输入；独立检索可以命中同一条正文，不因此新增身份。真正不同的事件、立场变化或独立用途才分别处理；判断、收藏资料与研究待办各有用途，即使出自同一句也应分别判断。跨目标脱敏仍是同一候选的不同投影，不再拆成通用版和项目版两个候选。

没有明确项目名的通用判断仍可路由到获准目标。项目归属未知与内容受众未知分别判断。缺少理由、结果、成熟论证属于未知字段，不是自动拒收理由。确实缺少对象、存在未消解纠正或受众不明时，保留候选并指出具体缺项。

## 数据与状态

这里只定义处理中的临时对象，不改变目标已有 schema：

- **输入**：稳定的本轮定位、来源角色、消息/材料范围。完整原文留在原来源。
- **候选**：本轮临时 ID、类型、输入引用、主体与对象、拟保存内容、未知项、应处理目标。
- **目标结果**：候选 ID、目标、最终状态、目标内容身份、判断依据、验证证据。

目标结果使用以下互斥状态：

| 状态 | 含义与条件 |
| --- | --- |
| `created` | 新身份已写入、校验并回读 |
| `updated` | 原身份实质修订，已校验并回读 |
| `duplicate` | 实际读取已有条目，目标身份和等价依据明确，无需更新 |
| `candidate` | 证据、目标接入或授权缺项，暂未保存；明确原因 |
| `skipped` | 明确不适合该受众或用户要求跳过；明确原因，避免泄露私密候选正文 |
| `failed` | 尝试处理失败或写入后验收失败；保留已完成步骤及恢复入口 |

处理中用待处理状态，最终回执不接受待处理。`candidate` 表示已明确缺项，不用于搁置已授权且合格的内容。未配置目标时用 `unconfigured` 作为临时目标并记 `candidate`；只输出模式用 `output-only`，不读取默认目标。

去重对象是目标中的相应内容身份。工程文件、同标签文章或相似话题不替代个人记录去重。补全保留身份，真实改变另建关联；重复运行先读目标，按内容幂等，不凭上轮“已保存”的聊天文字跳过核验。

每个目标独立完成；一个目标失败不回滚其他目标，也不把成功投影计为多条独立原创。写入前重读以保护并行变更，发生冲突就重新去重；不覆盖他人版本。恢复时从已失败阶段继续并核验目标当前内容，避免重复插入。

## 审计回执

自动模式在结束前创建一次临时 JSON 回执，使用下列字段。路径来自系统临时目录，不写入目标内容仓库；精确出处和敏感原文不进入回执，证据使用短引用。手动只输出模式可使用同一格式，用户要求不写任何文件时直接在回复中逐项核对。

```json
{
  "version": 1,
  "scope_complete": true,
  "expected_inputs": ["message-1"],
  "inputs": [
    {"id": "message-1", "candidate_ids": ["c1"], "reason": ""}
  ],
  "reviewed_kinds": ["record", "reference", "concept", "research", "excerpt"],
  "candidates": [
    {"id": "c1", "kind": "record", "source_ids": ["message-1"], "targets": ["personal"]}
  ],
  "results": [
    {
      "candidate_id": "c1", "target": "personal", "status": "created",
      "record_id": "target-stable-id", "reason": "本人明确的技术判断",
      "validation": "目标校验成功的工具结果引用",
      "readback": "目标内容身份及正文回读的工具结果引用"
    }
  ]
}
```

`expected_inputs` 来自阶段 1；每个输入只能有一个清单项。排除的输入 `candidate_ids` 为空，`reason` 必须说明具体原因。有候选时输入与候选的来源引用须双向对应。每个候选的每个目标必须且只能有一个结果。`duplicate` 需要 `record_id`、`existing_ref`（实际读取的目标位置）和 `reason`（等价依据）。完成项需要 `validation` 和 `readback`。同一目标、类型、内容身份本轮只保留一条最终结果，相关消息合并到候选；新建后补充仍计新增。

```bash
python3 <skill-dir>/scripts/audit_receipt.py <本机临时回执.json>
```

脚本退出 0 表示结构和状态一致，退出 1 表示须修复回执或继续未完成工作。输出按目标、类型汇总的数量；`completion` 为 `changed`、`no_new` 或 `attention`。候选待处理和失败会产生 `attention`，即使另有成功项也不能笼统报“已完成”或“无新增”。`skipped` 单独披露适当原因。

**能力边界**：脚本不能证明输入清单语义完整、原话正确归属、判断值得记录、授权充分，也不能仅凭证据引用验证外部写入。Agent 必须实际执行这些检查。回执是可核对的工作结果，不是语义正确性的证明；不声称已部署强制宿主 hook 或保证未来零漏记。

## 验证与维护

规则维护时按 [行为回归案例](regression-cases.md) 检查端到端决策；脚本测试验证范围截断、覆盖关系、状态门槛和统计。固定案例通过只证明这些案例，持续收到漏项时回到具体失败阶段修正，避免不断扩张无关规则。目标协议只定义字段、受众、现有操作和验收；不重新复制通用分类规则或隐式追加清单维护。
