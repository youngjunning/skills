# 每轮自动蒸馏

自动蒸馏是本轮内容处理，不是后台任务或会话结束事件监听。由用户的全局或项目指令启用，在主任务完成后、最终回复前执行一次。用户要求跳过或只输出时优先遵从。未来轮次是否执行取决于该轮实际读取的指令，不能仅凭安装声称已经运行。

## 目标与范围

默认只审阅本轮新增、纠正、用户明确保留的未解决问题及本轮指出的漏项；已有条目仅按候选所需去重，不每轮扫描历史会话、全部文章或技能目录。

本轮新写或实质修订文章时，把完成审查的实际正文及来源作为本轮输入，逐段找出读者理解文章所需、离开文章仍值得回看的概念解释。对每个这样的概念核对原始依据和适用边界，按概念笔记规则查目标已有卡片：等价内容记重复，缺失的关键信息补全原卡片，真正的新概念才新建。只有术语出现、普通名称或文章已完整解释且无独立回看用途时，记录具体排除理由。卡片引用实际文章的稳定身份与相关段落；文章所引原始资料若用于支撑卡片，也按目标出处规则保留。文章草稿或 Agent 文案不能单独证明本人已掌握、实践或认可该概念。若目标提供文章术语到卡片的关联方式，保存后按目标协议建立关联并验收；不为此自动改动其他站点。

默认配置可包含多个目标的根目录、接入文件、启用状态、受众、材料路由与写入授权。真实站点、主机、个人路径与内部规则留在本机配置，不进入通用技能。项目归属只能作为路由线索，不能代替内容授权。源目标停用时不探测其目录、映射与历史账本；其他获准目标独立执行。

逐目标检查接入协议，分别判断五类内容。跨目标传播只有在配置明确允许的方向和受众审查通过后进行；目标独立修订保留，原始私密片段不因已有公开摘要而公开。无法确认的材料只输出候选。未经配置，不追加文章同步、发布、Skills 清单或使用统计任务。

## 完成检查

按 [处理协议](pipeline.md) 的六个阶段执行；在最终回复前核对以下条件。审计回执只在本机临时目录保存，不新增永久台账、服务或全量扫描：

1. **输入覆盖**：列出本轮用户表达中的判断、选择、想法、纠正及明确保留请求，也列出本轮新写或实质修订文章的实际正文范围；绑定必要上下文和出处，包括本轮指出的漏项。不能只审阅最后一句、自己的总结或工具结果。摘录不完整时先定向恢复。
2. **五类分流**：逐项判断个人记录（其中单独检查价值观）、参考资料、概念笔记、研究待办、精选会话。对收藏与后续事项，主动核对本轮用户表达及文章正文是否出现明确收藏、可独立回看的概念解释、尚未解决而值得继续追的问题、以及目标允许保存的对话转折；不只查“收藏”“稍后”或“精选”等字面词。每个有价值候选明确归属和状态；普通执行命令、重复确认可排除，但命令中包含的技术选择仍需独立判断。
3. **目标与去重**：对获准目标查同事件、对象和立场，记录已有条目身份及是否等价；尚未查目标不能判重复。无具体项目的通用观点按其内容及受众选择目标，不仅因当前目录归属未知而拒收。
4. **逐项处理**：新增、更新、重复、候选待接入、受众不允许、失败分别有依据。已授权且满足条件的候选本轮完成保存；缺少未陈述的理由、量化结果或实施证据不妨碍保存观点。某一目标或类型不可用不阻断其他分支。
5. **结果核对**：保存项通过目标校验并回读；未保存项有具体原因；统计与这些结果一致。Git、部署、页面验收分别报告，未提交不等于未保存。

只有上述核对完成，且没有新增、更新、未处理候选或失败，才可报告“无新增”。对收藏、概念、研究和片段中没有候选的类别，内部检查时写明具体原因，例如本轮只提到术语、问题已解决、没有独立回看价值或目标未授权；不能用栏目原本为空来推断不必判断。因重复而无新增时，内部须有目标及已有条目 ID；回复可简短说明重复。已写入但校验未通过、未检查目标、仍待处理，均不能报成“无新增”。

完成后按处理协议生成回执，运行 `scripts/audit_receipt.py` 核对输入覆盖、候选去向、结果状态与统计。它不代替语义提取、受众审查或目标验证。维护或排查漏记时使用 [行为回归案例](regression-cases.md)，检查实际处理结果，不能只查规则文字是否存在。自动模式的回复将蒸馏结果放在“收尾”下；Git 项目和分支等收尾信息由调用方指令补充，不计入蒸馏条目。

## 统计口径

口径是本轮实际变更的内容身份，不是调用次数、扫描文件数、候选数量或历史总数。

- **新增**：本轮创建的新身份，写入、校验并回读通过。
- **更新**：本轮实质修订已有身份，写入、校验并回读通过。补全或状态变化计一次；反复写入同一身份仍计一次；新建后再修订仍只算新增。
- **候选**：有价值但未保存，注明缺目标、缺映射、授权或证据等原因。不能计入新增。
- **无新增**：五类已判断且没有可保存增量；不把未执行或失败包装为零。
- **部分完成/失败**：指出目标、类型及实际完成范围。写入但校验失败不计入成功数；保留修改状态并报告，不回滚他人修改。

以目标、类型、稳定 ID 去重，多目标分开列出，不把同一内容的跨目标复制混为多条原创蒸馏。记录、资料、概念、待办、片段分项统计；一个事项有独立用途的多种产物可以分别计数，但需要真实关联和内容。

默认仅报告本轮，不从历史 Skills 计数推导累计蒸馏。只有目标提供经核验的内容变更账本时才展示累计，并写明覆盖范围。提交、推送、部署和页面验收单独报告，不作为条目成功数。

## 回复格式

有变更时按实际分项，例如：

> 收尾：蒸馏记录新增 1；资料更新 1；研究待办新增 1；会话片段新增 1。已保存并校验至指定目标。

无变更时一行即可：

> 收尾：蒸馏无新增；本轮仅为重复确认。

有阻塞时示例：

> 收尾：蒸馏资料新增 1；研究待办候选 1（目标尚未接入，未保存）。

只列有变化或需要解释的类型，不固定输出五个零，不输出与本轮内容无关的 Skills 加载次数。例子仅说明格式，不是实际统计。
