# 证据与表达示例

以下为虚构示例，不授权写入示例数据。

| 输入与条件 | 应执行的决定 |
| --- | --- |
| Agent 给出三个选项，用户说“都做，先建记录” | 还原选项与顺序，不补造未表达的理由 |
| Agent 建议新增服务，用户只要求继续修复 | 不记为采纳新服务 |
| 资料以第一人称介绍一段工作 | 核对作者，不归为当前用户经历 |
| 用户问技术是什么，查到有复用用途的官方文档 | 个人记忆可无候选；获准时单独收藏文档 |
| 工具尚未采用，但用途和来源已核验 | 可作为会话发现资料；保留采用状态未知 |
| 概念有独立解释与可回查来源 | 可保存知识笔记并注明归属，例子与边界按需要提供，不声称用户已经掌握 |
| 本人明确说学到一种做事方法 | 可保存本人陈述的方法笔记，不补写实际执行或成效 |
| AI 独自整理有来源的方法 | 可作为 AI 辅助笔记判断，不能归于本人立场 |
| 只有术语提及或重复摘要 | 不制造知识笔记 |
| 同事件记录缺少上下文 | 补全原记录并保留身份，不包装成观点改变 |
| 本人明确改选另一方案并说明理由 | 保留旧记录，新增关联变化 |
| 同 URL 资料获得可靠新来源或纠正 | 更新原条目，不抹去主动收藏属性 |
| 目标支持资料，不支持知识笔记 | 资料按授权保存；笔记仅输出候选 |
| 用户要求只输出，机器上已有默认目标 | 输出候选，不读取或写入默认目标 |
| 目标不可用、接入映射不全 | 输出缺项，不猜其他仓库或新建存储 |
| 已提交代码，没有部署证据 | 只报告提交，不记录为上线结果 |
| 接收方不能获知精确出处 | 使用获准摘要或真实公共来源，原始出处不进入目标 |
| 某分支写入成功、另一分支校验失败 | 分别说明成功范围和失败状态 |

检查实际决定、来源与输出，不以出现规则关键词代替行为验收。

| 自动蒸馏场景 | 应执行的决定 |
| --- | --- |
| 新建资料后同轮补充两次 | 资料新增 1，不另计更新 2 |
| 同一内容保存到两个获准目标 | 分目标报告，不累计成两条独立知识 |
| 写文件成功但目标校验失败 | 报告未验收，不计已保存成功数 |
| 用户说“等有设备再验证这个问题” | 待办保存问题、设备阻塞和下一步，不伪造日期 |
| Agent 推荐研究一个方向，用户未回应 | 仅候选，不创建用户承诺 |
| 用户标记一句话，但后文纠正了它 | 连同纠正保留上下文，不孤立截取 |
| 自动发现好片段，目标没有自动收藏授权 | 仅输出片段候选 |
| 本轮仅确认上轮结果 | 无新增，一行说明；不扫描 Skills 或历史会话 |
