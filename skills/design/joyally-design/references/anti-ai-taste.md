# 反模板感检查

“AI 味”是对界面结果的主观描述，不是生成来源的判定。检查目标是找到可观察的任务、信息与视觉问题；颜色、圆角、渐变、卡片或插画本身都不是缺陷。[调研依据与推论边界](ai-taste-research.md)记录了本规则使用的一手来源。

## 生成前约束

新建界面在写代码或生成效果图前，把设计方向和任务条件放在同一份输入里：谁在什么设备上处理什么对象，首屏先看到什么依据、要完成什么动作，以及已有品牌、组件与内容约束。先选当前领域的骨架与一个视觉方向，再让生成工具实现；方向已定时沿用，改法明确的小改动直接执行。方向由产品事实决定，不把“干净”“高级”“去 AI 味”当成独立设计规格。

可把下面的短约束放在 Codex 会话开头或具体 UI 任务前，替换方括号；项目已有规范优先，缺失信息标明待确认：

> 写 UI 前先锁定设计方向：[用户与任务]；[首屏主角、判断依据、主动作]；[品牌、组件、主视口]；[视觉方向及其产品依据]。用实际内容组织首屏，让每个容器、装饰和文案承担可说明的职责。避免重复卡片、无语义侧条、空泛欢迎语和整齐假数据；必要的状态、品牌表达与可用操作保留。先交付一个方向的首屏，再按真实画面检查并修正。

外部“unslop”提示词包可以作为参考材料：先核对来源、许可和与项目规范的关系，再提取适用的规则；不能用未核对的整包替代当前产品事实。用户只提供方法摘要而没有原包时，按上述可核对的约束执行，不声称已经采纳原包全文。

## 先看任务，再看画面

1. 写出用户此刻要识别的对象、要作的判断、所需依据和下一步动作；使用实际内容，缺失时标明模拟数据。
2. 在目标视口与关键状态的真实画面上，按下表指出具体位置和视觉后果。只处理观察到的问题；既有品牌、组件、用户习惯和明确的视觉方向是判断依据。
3. 先修内容、顺序与页面骨架，再调整容器和组件，最后处理装饰。前后对照固定内容和视口，检查主要任务、窄屏、键盘与状态反馈是否仍完整。

| 检查项 | 识别线索 | 修改与保留条件 | 示例（虚构） |
| --- | --- | --- | --- |
| 任务焦点错位 | 大面积主视觉或单个指标抢走判断对象与操作入口的位置 | 让对象、依据和下一步先进入视野；重要指标确实支撑当前判断时保留 | 工单页把“累计 128 条”做成首屏最大卡片，待处理原因在下方 → 首屏先放待处理列表、原因和处理入口 |
| 重复容器 | 卡片内再套卡片，重复标题、边框或阴影；连续内容被拆成无法独立理解的小盒子 | 用一层容器、分组标题或行分隔表达关系；真正可独立浏览和跳转的集合项可以使用卡片 | “运行日志”卡片内又套“本次日志”卡片，逐条日志再套小卡片 → 一个日志区域加时间分组与行分隔 |
| 无语义侧边强调条 | 同级卡片边缘重复出现醒目竖条，却不区分状态、类别、当前位置或操作范围 | 用标题、间距或已有边界分组，移除无职责侧条；有语义的侧条保留，并配可见文字或图标 | “运行日志”和“测试工具”都加同样的粗侧条 → 去掉侧条；当前步骤的侧条可保留并标注“当前步骤” |
| 通用样式误套场景 | 页面套用了与真实任务不符的社交主页、营销首屏或组件库默认模式；品牌只剩换色 | 回到产品对象、现有组件与品牌参考；有意采用的通用模式能帮助用户时保留 | 航班处置页用欢迎语和大头像占据首屏 → 先呈现航班状态、待办和处理动作 |
| 解释性文案占据版面 | 标题上方的英文小标签、标题下的说明和对称摆放的文案重复已可见的信息，或用空泛承诺填补留白 | 逐句问“删掉后，用户是否会误解对象、依据、状态或下一步”；答案为否时删去或降级。操作含义不明时补明确的动作文字，必要说明保留在使用它的位置 | “数据总览中心 · 全方位监控平台运行状态”盖在请求量上方 → 直接显示“今日请求量”及有依据的数值；信封图标代表投稿时标出“投稿” |
| 空泛文案与整齐假数据 | 名称、时间、数值和按钮文案都可互换；数据缺少长值、空值、异常与真实动作 | 使用获准真实内容或明确标示的模拟数据，覆盖会影响布局和决策的边界；不把示例当成业务结果 | 每行都是“示例项目 · 100% · 了解更多” → 用不同长度、状态和动作的模拟记录检验列表 |
| 装饰代替反馈 | 只靠颜色、光效或徽章宣告成功、失败或处理中，用户看不出结果或恢复方式 | 给状态文字、作用对象与下一步；颜色和动效可辅助，但不独自承载含义 | 保存后仅把边框变绿 → 显示“已保存”与时间；失败时说明原因和重试入口 |

验收时写明每个被指出元素原本声称承担的职责、实际是否承担、修改后用户怎样更快完成任务。不要为了消除某种视觉风格而清空内容、抹掉品牌或移除必要状态。页面展示的前后示例是教学用虚构场景，不代表已经改动任何具体产品。

解释性文案的检查来自 [oil欧呦《如何使用 AI 做出有高级感的设计》](https://www.bilibili.com/video/av117608837946786) 约 01:46–03:11、20:19–21:06 的实践讲解。该视频提供设计案例和作者经验，不是对所有模型或界面的普遍测量；按当前页面的任务与画面判断是否删减。
