# 分层架构图

分层架构图回答“系统由哪些职责层组成，每层放什么”。把入口、能力、服务、数据按职责分层；身份、配置、交付、观测等贯穿多层的平台放在横向侧栏。若读者要确认具体调用和依赖，转用[系统架构关系图](system-architecture-relationships.md)；若要浏览主题归属，转用[思维导图](mindmaps.md)。

## 组织内容

1. 先确定读者和层次问题。每层写一句职责，再放同一抽象层级的节点。产品名、仓库名、框架、平台分别标明，不把同一产品拆成多个入口。
2. 按实际系统选择层数，通常为产品入口、领域能力、应用服务、数据资源。纵向顺序说明职责承接；只有经证实的调用才画有向连线。层与层之间可写“请求进入服务”等概括文字，但不能据此推断每两个节点直接相连。
3. BUC、权限、配置、Aone、CC、日志和监控等平台按职责放侧栏或独立横向带，不作为业务请求的后继层。调度平台可放服务运行区，明确“已开通”与“有 Job”是不同状态。
4. 同一技术选型与运行资源分开，例如 ORM 与数据库分别占位；用文字状态标明已选型、代码已接入、资源已开通、环境已部署、真实请求已验证或待核对。
5. 核对每个节点的来源与时间。用户确认的产品名称优先；运行状态以当前源码、配置或真实请求证据为准。

## Joyally 实现与验收

用语义 HTML 与 CSS Grid 绘制可编辑分层图，保留节点文字和职责说明。使用 Joyally Design 的字体、语义颜色、间距及卡片状态；颜色只编码类别，状态必须有文字。需要放进文章时交付独立 HTML，并可嵌入汇总页；需要静态图片时从同一源导出，避免手工维护两份内容。

桌面先保证每层标题、节点、侧栏在一个阅读宽度内清楚；窄屏按“业务层 → 横向平台”重排，保留阅读顺序。检查长名称、打印、离线打开和截图。交付时分别说明结构检查、浏览器画面检查与事实核对结果。
