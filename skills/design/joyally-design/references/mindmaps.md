# Joyally Design 思维导图

思维导图用来回答“一个主题分成哪些部分、每部分包含什么”。它以中心主题和层级分支组织知识。系统之间的调用、依赖、数据流与状态迁移使用[系统架构关系图](system-architecture-relationships.md)或相应 typed diagram，不用脑图的分支线冒充有向关系。

## 内容组织

1. 先写一句中心主题，再把信息归为 4–7 个同一抽象层级的主分支。产品、能力、技术、平台可以分别作为分支，但同一产品的多个仓库名不能冒充多个产品入口。
2. 主分支下控制在 2–5 个短节点；默认 3 层，必要时最多 4 层。节点写名词短语或简短动作，不复制文章句子。细节、证据和限制放在展开层或正文。
3. 一个节点只选一个主归属。跨分支关系另用正文或架构关系图说明；重复节点会让读者误以为是两个系统。
4. 已开通、已接入、已部署、已验证、待核对是不同状态。需要显示时在节点文案中写明，不只靠颜色区分。
5. 用户确认的产品名优先于仓库名。仓库、框架、平台放在产品节点下一级或附注；改名后核对源文件、导出图和引用文章。

## 可编辑格式

使用 Markmap Markdown 保存源文件，文件名建议 `<topic>.mindmap.md`。固定一个 `#` 作为中心主题，`##` 作为主分支，`###` 与短列表作为更深层节点。推荐 frontmatter：

```md
---
title: 系统能力地图
markmap:
  colorFreezeLevel: 2
  maxWidth: 300
---

# 系统

## 产品入口
- 桌面端：客户端产品
- 工作台：Web 管理入口
- 数字员工：任务执行入口
```

打开源文件可在 Markmap 或支持它的编辑器中折叠、缩放与编辑。需要独立 HTML 时，从同一 Markdown 渲染，保留源文件；不要维护两份内容不一致的手工节点。环境支持 Node.js 时可运行 `npx --yes markmap-cli input.mindmap.md -o output.html --no-open`，然后在浏览器核对实际结果。运行不可用时只交付源文件并说明 HTML 未生成，不把手写 HTML 冒充 Markmap 渲染结果。

## Joyally 视觉与验收

沿用[设计契约](../SKILL.md#设计契约)的语义颜色、正文可读性和品牌选择。分支颜色只帮助定位类别，不表示验收状态。避免一行铺开全部叶子节点；首次视图只展开到主分支，细节由用户点开。检查 1440px 桌面和窄屏下的文字尺寸、节点遮挡、缩放与键盘操作；提供文字纲要作为打印和无脚本 fallback。

交付时说明源文件、HTML 或静态导出分别是否生成和实屏验证。内容有项目事实时，标明来源与核对时间，不把推断或早期会话状态写成当前运行事实。
