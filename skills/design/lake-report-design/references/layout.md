# Lake Report layout reference

Lake Report 的“呼吸感”来自稳定的阅读节奏，而不是把所有区域做大。布局应让读者知道内容从哪里开始、下一段在哪里出现、哪些信息属于同一组，同时保持专业报告所需的信息密度。

## Layout contract

1. **先定阅读路径，再定容器**：默认顺序是结论或摘要 → 背景与范围 → 发现与证据 → 建议与限制。不要为了填满首屏，把次要信息提前或把内容拆成均等卡片。
2. **使用单一主容器**：桌面端正文宽度建议 `min(100% - 48px, 1180px)`；长文本阅读区域控制在 `68–78ch`，宽表格、代码和截图可以局部扩展并横向滚动。
3. **保持 8px 节奏**：组件内使用 `8/12/16px`，区块之间使用 `24/32/48px`。连续的标题、说明和内容至少保留一个 `16px` 的视觉间隔；主区块之间优先使用 `32px`。
4. **让高度由内容决定**：报告区块、摘要和证据容器不设置与内容无关的固定大高度；首屏只保证摘要完整，不强行制造 hero 留白。
5. **一层表面一个边界**：外层 canvas、主阅读 surface、局部 muted surface 各自承担一个层级。避免在卡片中再堆卡片；需要分组时优先用间距、分隔线或轻色背景。
6. **强调前后留白**：标题上方连接前文，标题下方连接正文；一个区块结束后先留出 `24–32px`，再开始下一个区块。不要让边框直接贴住相邻标题，也不要用连续阴影替代间距。

## Responsive layout

### Wide (`≥ 1024px`)

1. 保留单一主列；只有当侧栏能提供持续导航或上下文时才使用双列。
2. 主内容与可选侧栏之间保持 `24–32px`，侧栏不应压缩正文到低于 `60ch`。
3. 摘要可以使用两列，但证据和长文本回到单列阅读节奏。

### Medium (`640–1023px`)

1. 收窄主容器，保持 `24px` 页面边距和 `24–32px` 区块间距。
2. 将辅助侧栏移入正文或折叠为可展开区域，不要把所有桌面列硬挤在一起。
3. 多列卡片在内容变窄前换成单列或两列，保留标题与正文的清晰层级。

### Narrow (`< 640px`)

1. 页面边距为 `16px`，区块间距至少 `24px`；标题与首段之间保持 `12–16px`。
2. 导航进入正常文档流，不能遮挡标题或首个结论。
3. 宽表格、代码和截图使用局部横向滚动；不要缩小正文到不可读，也不要让整个页面横向溢出。
4. 卡片内 padding 使用 `16px`，控制高度不超过 `40px`，避免移动端出现大面积空白。

## Breathing-room checks

在交付前，用真实内容检查以下边界：

1. 最长标题换行后，标题与摘要、摘要与下一区块仍然有清晰间隔。
2. 空状态、单条发现和多条发现不会因为固定高度产生异常空洞。
3. 长段落、列表、代码和表格之间不会粘连，也不会被装饰性渐变降低可读性。
4. 390px 宽度下没有水平页面溢出；宽证据只在自己的容器内滚动。
5. 打印时移除粘性导航与外围氛围，保留正文间距，并避免标题与紧随其后的证据跨页割裂。

## Anti-patterns

1. 用 `min-height`、超大 padding 或空白 hero 强行撑满首屏。
2. 每个段落都做成同样大小的圆角卡片，导致阅读路径变成卡片网格。
3. 通过降低字号、行高或容器宽度解决内容过长。
4. 在长文本、表格、代码或截图后面放置高对比渐变、粒子或半透明装饰。
5. 只在桌面端调好间距，再让窄屏自动压缩或产生整体横向滚动。
