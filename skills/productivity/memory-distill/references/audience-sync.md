# 双向受众审查与文章同步

当目标同时包含公司内站与个人公开站，或本轮涉及文章同步、模块对齐时读取本文件。目标 schema 和模块可以相同；数据能否进入某个目标，取决于该目标的读者与源码可见范围。

## 先判断内容，再选择仓库

Git remote 只识别项目归属，不决定资料接收方。internal 是公司读者可访问的目标，不是个人私密资料库。保存、提交、上传附件和调用模型前均按接收方判断：

| 内容 | 公司内站 | 个人公开站 |
| --- | --- | --- |
| 已确认可向两类读者披露的文章、经历、知识资料 | 保存适合公司读者的版本 | 保存适合公开读者的版本 |
| 公司项目、业务资料、内部指标与内部原始证据 | 仅保存获准内部共享的内容 | 仅保存脱敏后仍保真的版本；不能脱敏则跳过 |
| 求职意向、面试安排、薪资谈判、私人联系方式、住址、证件、家庭及健康心理资料等个人敏感内容 | 未获针对公司读者的明确授权时拒收，已公开也不代表允许同步公司 | 同样逐项判断公开授权；私人资料优先留在明确配置的个人私有目标或本机 |
| 同时包含公司秘密与个人敏感资料的原始内容 | 不保存整份原文 | 不保存整份原文；必要精确映射留在已配置的个人私有位置 |

目标没有配置个人私有存储时，不新建数据仓库；只输出候选及跳过原因，不把公司目标当替代。来源字段、文件名、附件、截图、Git 历史、搜索索引、API 和模型上下文都属于披露面。private、draft 和 UI 隐藏只能改变展示，不能保护仓库中的原始秘密。脱敏结果仍暴露关键事实或改变作者意思时，跳过该方向。

Skills 的安装路径、项目分布及触发统计也按这张表审查。扫描范围或内部统计展示的既有授权，不扩展成披露私人项目、求职线索、原始会话或私人路径的授权；不合格明细在本机保留，目标只接收获准聚合结果。

## 共用协议与模块

两站沿用同一记录类型、字段含义、稳定 ID、时间精度、来源、关系、去重和真实变化规则。两站都支持同一套功能模块；UI、身份呈现、部署配置与接收方策略分别维护。模块存在不意味着填入相同数据，未获准的数据允许为空。

修改一端的 schema、蒸馏分支或功能模块时，核对另一端的对应实现和校验器。区分已对齐、缺失实现和目标策略差异；缺少 Wiki、工程资料、OKR 等模块时如实报告待实现，不能通过复制空文件或只改说明宣称能力已对齐。原始内部代码、环境配置、密钥及仓库历史不作为模块迁移输入。

## 文章增量同步

文章是独立同步分支，不因个人记录、收藏或 Skills 无新增而跳过。处理本轮新写、实质修订、明确撤回的文章与已知未完成项；默认不批量公开历史稿。

1. 读取两端的文章协议、现有同 ID 文章和本轮差异。以稳定文章 ID 定位，不以同标题判断同一文章。只做同步时保留 ID、真实日期、作者立场与未知项；脱敏后的标题和文件名可以不同。
2. 针对接收方检查全文、frontmatter、署名、来源、标签、链接、封面、配图、截图、附件、HTML 和资源映射。内部到外部移除内部身份、地址和未公开事实；外部到内部移除不允许公司知道的个人信息。公开可读本身不是公司同步授权。
3. 直接准备目标版本并逐段审核，使用补丁写入；不先复制未脱敏原文、附件或 Git 历史再删除。内部精确出处不得留在公开来源字段；个人私密出处也不得留在公司仓库。需要精确映射时使用获准的原始证据位置。
4. 保留有据的公共引用；删除、改写或替换不适用引用，并核对目标实际文章 ID。封面和附件必须适合目标受众、具备使用权限并能在目标访问；内部 CDN 资源不得直接外传，先审查图片内容再选择目标允许的资源位置。
5. 分别执行目标要求的内容检查、测试、类型检查与构建，回读目标源稿及必要页面。只有验证后的目标内容才能提交和推送。部署、线上阅读和 ATA 同步按各自约定报告。
6. 用 ID 比较本轮应同步的真实内容与已审阅版本；两端字节不同可能是正确脱敏结果，同 ID 存在也不证明已同步。修订时重新审核，不覆盖目标独立修订；出现冲突先保留双方版本并解决事实与受众范围。撤回时核对两个方向，不自动删除只在目标独立维护的文章。

最终分别报告两个方向的文章数量及状态：已同步、无本轮待同步变更、因受众限制跳过、或未完成及原因。流程由当前会话执行，不声称有后台监听或未来会话触发保证。
