# 项目方案管理

本协议适用于正在处理的项目。蒸馏技能负责将讨论和执行证据写回原方案，使下次能继续；工程流程负责需求分析、技术取舍、spec、拆票和实施。方案正文是项目资产，个人资料站按授权保存定位索引。方案保存与用户采纳、实现完成是不同结果。

## 触发与范围

当本轮提出需要跨轮推进的方案、作出方案选择、实质调整范围、推进实现或验收，或明确暂缓/结束时，进入本流程。用户明确要求“保存方案”“更新方案”“找上次方案”也适用。一次性问答、普通进度查询、机械修改、提交推送请求没有方案增量时，不创建空方案。

自动模式在主任务完成后检查一次；只核对本轮关联方案及必要出处。用户只要求讨论或暂不实施时仍可在已授权项目内保存讨论状态；用户要求只输出或不落盘时遵从。记录讨论不授权实施、部署、联系他人或跨受众传播。

## 执行步骤

1. **定位原方案。** 从当前任务及项目 AGENTS、tracker、已有方案目录和关联链接确认项目与原文。优先使用现有稳定身份；只搜索相关标题、对象和来源。找到原文后先读当前版本；不能把聊天标题或当前目录当成已确认的项目。缺少项目时保留已有聊天定位并说明缺项，不扫描其他仓库猜归属。
2. **补齐能继续工作的内容。** 按工程流程给出的结果更新目标与范围、约束、实际讨论过的备选及决策依据、未决问题、当前进展、证据和下一步。区分用户选择、AI 建议、假设与已验证事实；没有采纳证据的推荐保留为待讨论。原文尚不存在时沿用项目文档协议；未规定位置时可用项目 `docs/plans/` 保存最小原文，不为此另建服务、数据库、tracker 或强制配置。
3. **核对状态。** 复用项目已有状态及迁移规则。讨论、设计、实施、待验收、受阻、暂缓和完成是可映射语义，不强制项目采用这些枚举。只按用户明确决定或实际执行/验收证据转换状态：有代码不等于已部署，测试通过不等于业务完成；阻塞需写具体条件与恢复动作。改变决定时保留必要的原决策及替代关系，不静默抹去历史，也不把每次重试新建成方案。
4. **保存项目原文。** 更新同一文件或原有记录，保留其他人的改动、既有版本和引用。最近核对日期对应实际回查，下一步写成具体动作及阻塞条件。方案拆票使用项目指定的工程流程及其确认策略；本技能不自行创建、关闭或改写任务票据。原文写入受阻时保留已有文件/聊天定位，报告未完成部分。
5. **维护获准索引。** 读取本机目标配置及接入说明中可选的“项目方案”映射，审查接收受众。按项目与原方案身份去重，保存项目、标题、原文位置、最近核对状态、核对日期与下一步；指向项目原文，正文不复制到个人文章、知识笔记或中央索引。推进、暂缓和结束更新同一身份，终止方案保留必要历史。索引未配置或不适合受众时，项目原文可独立完成；说明未收录原因，不自建目标栏目或扩大公开授权。
6. **验证与交付。** 按各仓库协议检查链接、格式、状态与证据一致性，并回读原文与实际更新的索引；Git、部署及页面分别核验。报告本轮实际新增、更新或未变的方案，以及原文/索引各自结果和具体下一步。方案项不塞进五类蒸馏候选凑数，结果单独报告；用户在方案中的明确判断仍独立按个人记录规则去重。

## 目标接入

项目位置、受众、字段和状态映射来自项目及目标接入，通用技能不固化真实仓库、个人路径或网站。可选索引接入应声明数据文件、身份与状态映射、原文定位字段、校验回读方法和已有 Git 权限。没有中央资料目标不影响已获授权的项目原文维护；索引失败也不回滚已完成的原文更新。

记录最近核对时的状态，不承诺后台实时跟踪。下轮涉及同一方案时重新核对原文；没有本轮证据时不把旧索引的“实施中”写成实时结论。不开展全项目巡检、历史整库补录或自动跨站同步，除非用户另有明确范围授权。
