# 独立 Agent 合成场景评测：2026-11-02

## 方法与结果

三个独立 Agent 使用不含主会话历史的上下文，分别执行 R1–R7、R8–R14、R15–R20。提供原始合成输入和目标条件，不提供预期答案；允许读取 Skill 与处理协议，禁止读取回归答案表、其他组报告及真实个人配置和数据。

每案在隔离临时目录创建目标与验证器，实际执行候选提取、目标查询、写入或明确不写入、校验、回读和回执审计。主 Agent 对照预先存在的验收条件复核产物。首轮 **19/20 符合语义预期**，R2 的候选粒度不符合预期；全部 20 案回执结构审计通过。这一区别表明结构通过不能替代语义验收。

修正规则后，换组复测 R1、R2、R9、R20；四案均符合预期。最终 20 个既定场景均有符合预期的执行结果，其中 16 案沿用首轮结果，4 案使用复测结果，并非声称全量又运行了一轮。Python 自动测试另有 23 项，全部通过。

## 问题与修复

R2 首轮执行者认为通用判断与项目判断可以分别检索，因而赋予两个身份。原协议允许多句合并，但没有明确何时应合并；结果是同一连续事件被过度拆分，新增统计膨胀。

修复位于 [处理协议](pipeline.md) 的候选粒度规则：按事件和独立用途确定身份；同一立场从通用观点落到当前项目时合并，正文保留两层信息；检索需求本身不成为拆分依据。不同事件、真实立场变化和不同类型的独立用途仍分别处理。交叉复测 R9 和 R20 检查了过度合并风险。

R19 的恢复由 Agent 实际补跑目标校验和回读，审计器不替 Agent 执行这些动作。本轮未创建新身份或实质改文，因此报告重复与零新增，同时说明补验成功。

## 证据与限制

隔离运行保留各案例的原始合成材料、目标前后内容、验证输出、回读、receipt 和审计输出；公开源仅保存本摘要，不复制本机路径、执行标识或真实用户材料。

这轮验证覆盖指定的 20 个合成场景，以及修复后的 4 个交叉复测。它不证明真实站点接入、未来所有表达的召回率、宿主强制执行或零漏记。临时目标 schema 由测试接入定义，不替代生产目标校验。文档资料使用题设的本地合成来源，未访问或验证真实网站。
