# 设计质量工作流

本文件改编自 [Impeccable](https://github.com/pbakaus/impeccable) 的设计指导；来源与修改说明见 [来源记录](../vendor/impeccable/UPSTREAM.json)。它是 Joyally 的工作方法，不是 Impeccable 命令执行入口。使用当前项目的工具和校验，不依赖上游 CLI、检测器、hooks、评审存储或多 Agent 编排。

## 确定方向

先读取项目已有的品牌、tokens、共享组件和代表性页面；存在 PRODUCT.md、DESIGN.md 时按需读取，不为本流程强制新建。确认目标用户、主要任务、使用环境和改动范围；只有影响方案且无法从项目推断的缺项才询问。

- 阅读场景：优先正文节奏、证据结构、舒适行宽和稳定导航。
- 操作场景：优先扫读、状态辨认、信息密度、输入效率和错误恢复。
- 展示或说服场景：围绕真实产品价值建立鲜明的构图、字体或图像重点，让读者看见主张与下一步。

用一句话明确本次视觉方向及其与任务的关系。新页面以真实内容验证方向；已有页面先保留其身份与行为，精修请求不隐含重做品牌或信息架构的授权。

## 按任务选择动作

以下名称是工作模式，用户可以用中文直接描述，无需安装斜杠命令。

| 意图 | 工作方式 | 完成条件 |
| --- | --- | --- |
| critique：评价设计 | 先看实际渲染和主任务路径，再核对源码；判断层级、辨识度、连贯性、认知负担与文案 | 每条结论指出位置、观察、用户影响与改进方向；审美偏好与功能缺陷分开 |
| audit：技术审计 | 检查无障碍、性能、主题、响应式和实现一致性 | 缺陷可复现；标明检查工具、条件、证据及未测范围 |
| polish：精修 | 按下面的修复顺序改善完整路径 | 保留既有视觉方向；重新走通修改后的路径与受影响状态 |
| typeset / clarify：排版与文案 | 调整文字角色、断行、行距与术语；按钮写清动作，错误写清问题及恢复方式 | 长文本、中文及实际本地化文本可读；事实、数字和承诺保持准确 |
| adapt / harden：适配与健壮性 | 检查容器变化、输入方式、字体缩放、缺失数据、慢请求和权限受限状态 | 覆盖项目真实支持的尺寸与状态；仿真和真机证据分别报告 |
| bolder / quieter / distill：增强、收敛或简化 | 调整一个有任务依据的视觉重点，或移除竞争性装饰与冗余层级 | 主任务更清楚；保留必要信息、操作和品牌辨识 |
| animate / delight：反馈与动效 | 用动效解释因果、位置变化或完成状态，检查中断和减少动态效果 | 反馈不阻塞操作；减少动态效果时仍能理解状态 |
| extract / optimize：复用与效率 | 重复模式回到已有 tokens / primitives；按测量处理资源、布局或渲染瓶颈 | 改动落在最窄的正确层；无证据时不新增抽象或性能依赖 |

仅请求评审时交付问题与建议；请求修复时直接完成已授权范围。避免为了套用模式扩大任务。

## 评审与修复顺序

先完成视觉和任务判断，再结合静态检查或运行测量，减少检测结果对审美判断的干扰。检查工具未发现问题，不等于界面质量已通过。

1. 任务阻塞、误导状态、数据风险和不可访问路径。
2. 缺失的加载、空、错误、成功、禁用与权限状态。
3. 导航、层级、响应式和设计系统漂移。
4. 排版、间距、图像、图标与动效的一致性。

操作区先区分“当前状态”和“下一步动作”：状态用文字或标记持续可见，按钮用动词说明点击后的变化；暂停、关闭等可恢复状态应有清楚的恢复入口。多个操作挤在数据单元格或窄容器中时，先调整分组与容器层级，再决定按钮样式。用真实的启用、暂停、加载和错误数据核对，不能只看默认态截图。

修复前区分：缺少可复用 token、绕过共享组件、流程模型不一致、局部实现缺陷。重复问题回到共同来源；局部例外不自动升级为全局设计规则。

评审按 P0（阻断任务）、P1（严重影响使用或已核实的无障碍缺陷）、P2（有替代路径的局部问题）、P3（视觉细节）排序。每项写出页面或组件位置、证据、影响、建议；缺少运行证据时标为待验证，不给未经检查的维度打满分，也不宣称全面符合标准。

## 视觉检查

- 先看主动作与阅读顺序，再看装饰。相同尺寸的卡片、指标大字、编号和图标应表达真实分组、顺序或信息，不能靠替换文案就套用到任意产品。
- 使用项目字体与文字角色。阅读型正文检查行宽与段落节奏，操作型界面检查标签与数据对齐；中文行宽按真实字形验证，不机械照搬英文字符数。测试长标题、字体回退、缩放和窄容器。
- 从语义 tokens 取颜色与表面；在实际背景上检查正文、次级文字、控件和焦点。状态同时通过文字、形状或图标表达。
- 相关内容靠近，不同组之间留出明确间隔；同一角色的间距、圆角与层级保持一致。边框、阴影、材质服从已有系统。
- 统一图标家族与视觉重量。图片保留正确比例、占位尺寸和替代文本；装饰图与承载信息的图像分别处理。
- 检查真实数据、可用按钮、键盘焦点和错误恢复。移动端需验证实际手势；视口截图只能证明布局。
- 渐变、玻璃、系统字体、卡片与数字指标均由品牌和使用场景决定，不套用上游一刀切的审美禁令。原生平台继续遵循 Joyally 的平台参考。

## 验证与交付

复用 [统一验收](validation.md) 检查受影响路径与状态。技术审计中，性能结论来自测量，主题检查限定于产品支持的模式；Web 工具的结果不能替代原生无障碍或设备检查。报告源码检查、实际渲染、交互与设备证据各自覆盖范围。

交付说明改了什么、为什么、如何验证，以及仍未验证的部分。当前流程没有 Impeccable detector 或评分归档，不能声称运行了上游检测器、通过其完整审计或获得其评分。
