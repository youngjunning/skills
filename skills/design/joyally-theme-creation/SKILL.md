# Joyally 主题制作

主题是同一产品任务的一套可运行界面表达，包含信息层级、布局、导航、组件形态、材质、字体、图像、动效与语义色。配色预设只是其中一层。使用本 Skill 时同时遵守 [Joyally Design](../joyally-design/SKILL.md) 的平台选择、组件来源与可读性契约；进入项目先读项目指令和现有设计规范。本 Skill 聚焦主题从取材到验收的过程，不扩大用户要求的页面、平台或发布范围。

## 1. 固定任务与比较基线

确认产品受众、主要动作、真实内容、信息密度、目标设备、既有品牌及本次可改变的范围。选择一个能代表主要任务的页面或流程，记录它在现有主题中的内容顺序、导航、关键组件和状态。用户只要求主题说明时交付规范；已授权实现时完成代表性页面并按需扩展。详细的新建、回改和存量项目路径仍按 [完整设计流程](../joyally-design/DESIGN_PROCESS.md) 选择。

## 2. 从参考提炼主题语法

收集可追溯且适合目标受众的参考，区分真实照片、品牌素材、生成示意与实现素材。观察空间关系和视觉组织，不直接把照片色值或商标贴到控件上。为主题记录：

1. 构图与空间节奏：轴线、留白、框景、错层、曲线、拼贴或其他有来源的组织方式。
2. 信息层级与阅读路径：首屏主角、下一步动作、密集内容如何落在稳定表面。
3. 材质、字体、色彩与动效：各自出现的位置、强度和禁用场景。
4. 与已有主题的关系：哪些规则属于该主题，哪些是产品必须共享的行为。

例如香奈儿风从包袋、山茶花、珍珠、巴黎夜景与杂志排版提炼不等宽拼贴和黑白暖金节奏；服装与织纹只供局部细节参考。景观主题可从桥的水平长轴、园林框景或山脊斜线提炼页面结构，而非只抽取湖蓝、瓦灰或雪白。现有主题细则见 [视觉语言](../joyally-design/references/visual-language.md)、[香奈儿风](../joyally-design/references/fashion-xiaoxiang.md)和对应素材目录；这些是示例，不是其他品牌的默认模板。

## 3. 先证明主题有结构差异

拿**同一内容、同一任务和同一视口**与已有主题并排比较，先画或实现代表性页面的首屏、主要内容区和一条关键操作路径。围绕主题语法决定布局、导航、信息顺序、密度和关键组件的组织方式；不要先复制上一套 DOM，再只换 CSS 变量、背景图和圆角。

验收时遮去色彩与装饰图片，首屏、内容区及关键操作中仍应看得出贯穿页面的结构区别，并能说清它如何帮助该主题中的阅读或操作。只在一张卡片上换形状或只在首屏换图片不算整套主题。若用户仍感到“换了配色”，回到信息层级、构图和组件结构重新设计。保持相同的业务能力、内容事实与操作语义；视觉差异不能以藏掉功能或破坏可读性换取。

## 4. 落到 token 和自有组件

按 [统一 token 契约](../joyally-design/references/token-contract.md)建立 `Seed → Map → Alias → Component`：参考色与材质先形成 seed，派生悬停、按下和明暗映射，再接入画布、正文、操作、焦点、选中、成功、警告和错误等语义角色，最后由组件消费。检查实际渲染与计算样式，不能以色卡数量或 CSS 变量存在证明覆盖。

按目标平台选组件基础；React Web 项目依照 [组件工作流](../joyally-design/references/component-workflow.md)。shadcn/ui 可提供可访问的基础控件，Joyally 仍须设计自己的页面组合和关键组件细节：内容分区、标题与数值层级、间距、边框与表面、图标、密度、响应式处理，以及 default、hover、pressed、selected、focus、disabled、loading、empty、error、success 状态。关键组件要能体现主题的空间与材质规则，而不只是替换 `primary` 色。保留底层键盘、表单和辅助技术行为；不为“自有”重写所有基础控件。

需要宣称基础组件“齐全”时，按目标项目所用版本的官方组件目录和实际源码逐项核对，区分基础控件、组合组件、仅展示样例与尚未接入项。缺少的组件或语法能力明确列出，不用旧快照数量、预览卡片或换色示例充数。

## 5. 代表页验证后扩展

先在真实内容与关键状态中验证代表页，再推广到其他页面。用相同内容和视口保存主题并排截图，检查结构区别是否稳定；分别检查桌面、窄屏、浅深色、长文本、键盘、缩放、减少动态效果及高对比设置。表单、浮层、导航和状态反馈需要实际操作；正文、表格、代码与证据保持可读的不透明表面。完整检查按 [验收契约](../joyally-design/references/validation.md)。

交付时按实际任务提供主题规则、与现有主题的差异、token 映射、关键组件及状态、代表页画面和操作结果。分别说明设计规范、源码、静态检查、构建、真实页面、部署和线上状态；未验证的环节保持未验证。
