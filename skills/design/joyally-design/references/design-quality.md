# Joyally Design 专项质量检查

设计任务的领域、方向、组件、状态、精修、截图、评审和规范按 [完整设计方法](fused-method.md) 与 [能力路由](capability-routing.md) 执行。出现下列问题时补充检查。

## 与主流程的关系

| 专项主题 | 主路径 | 补充边界 |
| --- | --- | --- |
| 评价、精修、强化、收敛、动效 | `task-review.md`、`visual-polish.md`、`motion.md`、`iterate.md` | 已由主流程覆盖，不单独执行同义流程 |
| 排版与文案 | `visual-language.md`、`visual-polish.md`、`interaction-and-state.md` | 补真实中文、本地化、长值与承诺准确性的检查 |
| 响应式与状态 | `layout-and-viewport.md`、`interaction-and-state.md` | 补字体缩放、输入方式变化、权限受限、慢请求等健壮性边界 |
| 技术审计、复用、优化 | 截图、设计规范与实现检查 | 补可复现的性能、资源、无障碍和实现一致性审计 |

## 按需补充

1. **文字与本地化**：当任务包含文案或排版时，检查中文断行、长标题、真实名称、术语一致、按钮动作和错误恢复说明。保留事实、数字、引用与承诺；在实际字体和目标宽度下看。
2. **健壮性**：当页面使用动态数据、权限或多种输入方式时，检查字体放大、键盘与触控、缺失数据、慢响应、权限受限和操作中断。状态要出现在相应范围，失败后能继续。
3. **技术审计**：用户要求技术审计，或视觉问题可能由资源、布局或渲染导致时，测量性能和资源，检查无障碍、支持的主题、响应式及组件实现一致性。写清工具、条件、证据和未测范围；没有测量就不作性能结论。
4. **修复排序**：同一次评审的可复现问题按 P0 任务阻断、P1 严重使用或无障碍问题、P2 有替代路径的局部问题、P3 视觉细节排列。每项给位置、观察、用户影响、建议和证据。这个排序用于交付，不改变主流程的评审方式。

重复问题先检查共享 token、primitive 与状态模型，局部例外保留在局部。网页截图不证明键盘和真实触控，源码检查不证明实际渲染；设备、交互、构建和测量各报告已核对的范围。

没有运行第三方 detector、hooks 或评分归档时，不声称取得第三方评分。本文件始终作为 Joyally Design 的专项检查使用。
