# Joyally Design report language

Joyally Design governs how a report looks, reads, and exposes evidence. The report's subject, terminology, actors, workflow, and claims come from the user's material.

## Content hierarchy

1. Lead with the decision, conclusion, recommendation, or message the reader needs most.
2. Give context and scope before detailed analysis when the conclusion depends on them.
3. Keep each claim close to its supporting data, citation, screenshot, trace, example, or methodology.
4. Separate verified facts, interpretation, recommendations, and unknowns.
5. End with concrete next steps only when the report calls for action.

Common section patterns are optional compositional tools:

| Report type | Useful reading order |
| --- | --- |
| Status or project update | Summary → progress → evidence → risks → next actions |
| Technical analysis | Conclusion → context → method → findings → evidence → recommendation → limitations |
| Research report | Abstract → question → sources/method → synthesis → implications → references |
| Proposal | Recommendation → problem → options → trade-offs → plan → decision required |
| Review or audit | Verdict → scope → findings → evidence → remediation → unverified boundaries |

Rename, reorder, or omit sections to match the material. Never force a generic report into experience-governance terminology.

## Evidence semantics

1. Use stable visual roles for summary, finding, evidence, metadata, risk, recommendation, and appendix.
2. Pair color with a textual label, icon, or shape when it communicates status or severity.
3. Keep provenance visible: source, date, scope, method, sample size, identifier, or link when supplied.
4. Place large datasets, logs, and exhaustive references in an appendix when they interrupt the main decision path.
5. Do not turn illustration, decoration, or branded character art into proof.

## Copy

1. Preserve the vocabulary of the subject and the author's level of certainty.
2. Prefer concrete nouns and verbs over generic promotional language.
3. Keep technical identifiers, figures, citations, and qualifiers unchanged unless the user asks to revise them.
4. Use headings that state the point of the section, not a decorative slogan.
5. Do not insert Joyally Design, 产品专属, experience governance, digital employees, agents, or automation concepts merely to make the report feel branded.

## Visual identity boundary

Joyally Design identity comes from composition and treatment: mist-white canvas, joyally-teal accents, deep lake text, quiet gray-blue structure, restrained warm states, compact professional density, precise borders, and controlled atmosphere. A report about finance, architecture, research, operations, strategy, or any other subject should keep its own domain language.

Use product logos, character art, screenshots, or named workflows only when they are part of the source material or explicitly requested.

## Anti-patterns

1. Rewriting a neutral report as a 产品专属 product story.
2. Adding experience-governance workflows to unrelated content.
3. Replacing evidence with branded illustration.
4. Blue-purple neon used as generic AI decoration.
5. Scenic imagery used behind long text, tables, code, or evidence.
6. Glass cards nested inside other glass cards.
7. Every section represented by an equal rounded card.
8. Restyling that changes facts, ordering, identifiers, citations, links, or behavior.
